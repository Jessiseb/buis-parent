# 配置与密钥部署说明

本项目**不在代码仓库中存放任何真实凭据**。所有密码、API Key、服务器地址均通过环境变量注入。

## 一、首次部署前必须完成的凭据轮换

> 仓库历史中曾出现过下列凭据。若已推送到公开仓库，必须先在对应平台吊销（rotate）并重新签发，**仅清理 git 历史是不够的**。

| 凭据 | 平台 | 操作 |
|---|---|---|
| 百炼 API Key | 阿里云百炼控制台 | 禁用旧 Key，签发新 Key → `ALIYUN_AI_API_KEY` |
| 阿里云 OSS AccessKey | 阿里云 RAM | 禁用旧 AK，签发新 AK/SK → `ALIYUN_OSS_ACCESS_KEY_ID` / `ALIYUN_OSS_ACCESS_KEY_SECRET` |
| Coze 个人访问令牌 | Coze | 撤销旧令牌，签发新令牌 → `COZE_TOKEN` |
| 文心智能体 appId / 密钥 | 百度智能体平台 | 重建应用或重置密钥 → `WENXIN_APP_ID` / `WENXIN_APP_SECRET_KEY` |
| MySQL root 密码 | 数据库服务器 | `ALTER USER 'root'@'%' IDENTIFIED BY '<新密码>';` → `DB_PASSWORD` |
| Redis 密码 | Redis 服务器 | `CONFIG SET requirepass '<新密码>';` → `REDIS_PASSWORD` |
| 邮箱 SMTP 授权码 | QQ 邮箱 | 重新生成授权码 → `MAIL_PASSWORD` |
| Sa-Token / JWT 密钥 | 自签 | 重新随机生成 → `TOKEN_SECRET` / `SA_TOKEN_JWT_SECRET` |

同时需要检查：
- 三台数据库服务器（`43.136.119.58`、`119.91.227.162`、`42.194.233.38`）的 **安全组与防火墙**是否暴露了 3306/6338 到公网，建议只允许内网或白名单 IP 访问。
- Druid 监控台原密码 `123456` 强度过低，需改。
- `sys_user` 表中 admin 等内置账号的初始密码是否为弱口令。

## 二、环境变量清单

完整清单见仓库根目录 [`.env.example`](.env.example)。必填项：

```
DB_HOST              数据库地址（不含端口）
DB_PORT              数据库端口，默认 3306
DB_USERNAME          数据库用户名，默认 root
DB_PASSWORD          数据库密码        ← 必填
REDIS_HOST           Redis 地址        ← 必填
REDIS_PORT           Redis 端口，默认 6338
REDIS_PASSWORD       Redis 密码，可留空
TOKEN_SECRET         令牌签名密钥      ← 必填
SA_TOKEN_JWT_SECRET  Sa-Token JWT 密钥 ← 必填
ALIYUN_AI_API_KEY    阿里云百炼 API Key ← 必填
ALIYUN_OSS_ACCESS_KEY_ID      OSS AccessKeyId     ← 必填
ALIYUN_OSS_ACCESS_KEY_SECRET  OSS AccessKeySecret ← 必填
COZE_TOKEN           Coze 访问令牌     ← 必填
WENXIN_APP_ID        文心智能体 AppId  ← 必填
WENXIN_APP_SECRET_KEY 文心智能体密钥   ← 必填
MAIL_USERNAME        发件邮箱
MAIL_PASSWORD        邮箱授权码
DRUID_PASSWORD       Druid 监控台密码   ← 必填
```

生成随机密钥：

```bash
openssl rand -base64 48
```

## 三、注入方式

### 方式 A：环境变量（推荐，容器 / systemd 场景）

**Linux + systemd**，在 `buis-admin.service` 中：

```ini
[Service]
Environment="DB_PASSWORD=xxx"
Environment="SA_TOKEN_JWT_SECRET=xxx"
Environment="ALIYUN_AI_API_KEY=sk-xxx"
# ... 其余变量同理
ExecStart=/usr/bin/java -jar buis-admin.jar
```

也可以用独立文件（权限设为 600）：

```ini
EnvironmentFile=/etc/buis/buis.env
```

### 方式 B：Spring Profile 覆盖（本地开发）

复制模板并填写，本地文件已被 `.gitignore` 排除：

```bash
cp buis-admin/src/main/resources/application-prod.yml \
   buis-admin/src/main/resources/application-local.yml
```

然后在 `application.yml` 中开启：

```yaml
spring:
  profiles:
    active: test
    include: local
```

### 方式 C：IDE 启动（本地开发）

IntelliJ IDEA → Run/Debug Configurations → Environment variables，填入所需变量。

## 四、验证配置是否生效

启动日志中不应出现任何明文凭据。若必填变量缺失，应用会在启动阶段直接失败（这是刻意设计，避免带着空密码上线）。

```bash
# 启动前自检
env | grep -E "DB_PASSWORD|SA_TOKEN_JWT_SECRET|ALIYUN_AI_API_KEY"
```

## 五、清理 git 历史

若凭据已进入 git 历史（已推送到 GitHub / Gitee），在**完成第一步的凭据轮换后**执行：

```bash
bash scripts/purge-secrets-from-history.sh
```

脚本会先自动备份 `.git`，再重写全部提交历史。执行后需 force-push 到远端所有分支：

```bash
git push --force --mirror <remote-url>
```

**注意：**
- 已被人 fork 或 clone 的副本无法远程清除，需要通知相关人员自行清理。
- Gitee 上 master 分支受保护，需临时在仓库设置中解除保护后再推送。
- 轮换凭据是第一步，也是唯一能真正止损的一步——清史只解决"暴露面"，不解决"已被使用"。
